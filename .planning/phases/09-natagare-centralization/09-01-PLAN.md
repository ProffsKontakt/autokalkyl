<task type="auto">
  <name>Task 2: Create migration with duplicate detection and data transformation</name>
  <files>prisma/migrations/[timestamp]_natagare_global_scope/migration.sql</files>
  <action>
Create a Prisma migration that:

1. Create the ApprovalStatus enum type
2. Add new columns with defaults
3. Make orgId nullable
4. Add the approvalStatus index
5. Migrate existing data:

Migration SQL logic:
```sql
-- Create ApprovalStatus enum
CREATE TYPE "ApprovalStatus" AS ENUM ('APPROVED', 'PENDING', 'REJECTED', 'DUPLICATE_REVIEW');

-- Add new columns
ALTER TABLE "Natagare" ADD COLUMN "globalScope" BOOLEAN NOT NULL DEFAULT false;
ALTER TABLE "Natagare" ADD COLUMN "approvalStatus" "ApprovalStatus" NOT NULL DEFAULT 'APPROVED';
ALTER TABLE "Natagare" ADD COLUMN "requestedByOrgId" TEXT;
ALTER TABLE "Natagare" ADD COLUMN "approvedAt" TIMESTAMP(3);
ALTER TABLE "Natagare" ADD COLUMN "approvedByUserId" TEXT;

-- Make orgId nullable
ALTER TABLE "Natagare" ALTER COLUMN "orgId" DROP NOT NULL;

-- Add index on approvalStatus
CREATE INDEX "Natagare_approvalStatus_idx" ON "Natagare"("approvalStatus");

-- Flag duplicates: natagare names that exist in multiple orgs
UPDATE "Natagare" n1
SET "approvalStatus" = 'DUPLICATE_REVIEW'
FROM (
  SELECT name
  FROM "Natagare"
  GROUP BY name
  HAVING COUNT(DISTINCT "orgId") > 1
) AS duplicates
WHERE n1.name = duplicates.name;

-- Migrate non-duplicates to global scope
-- Keep the first one (by createdAt) as the global version
WITH ranked AS (
  SELECT id, name, ROW_NUMBER() OVER (PARTITION BY name ORDER BY "createdAt" ASC) as rn
  FROM "Natagare"
  WHERE "approvalStatus" = 'APPROVED'
)
UPDATE "Natagare" n
SET
  "globalScope" = true,
  "orgId" = NULL
FROM ranked r
WHERE n.id = r.id AND r.rn = 1 AND n."approvalStatus" = 'APPROVED';

-- Mark remaining (non-first) duplicates for review too
UPDATE "Natagare"
SET "approvalStatus" = 'DUPLICATE_REVIEW'
WHERE "globalScope" = false AND "approvalStatus" = 'APPROVED'
  AND name IN (SELECT name FROM "Natagare" WHERE "globalScope" = true);
```

Create the migration using: `npx prisma migrate dev --name natagare_global_scope --create-only`

Then replace the generated SQL with the above logic. This ensures:
- One global natagare per unique name (the oldest by createdAt)
- All other same-name natagare flagged as DUPLICATE_REVIEW
- Super Admin can resolve duplicates in Plan 02

If database is unreachable during execution, create the migration file manually (as done in 08-01).

- Returns all natagare where `approvalStatus IN ('PENDING', 'DUPLICATE_REVIEW')`
- Super Admin only
- For approval dashboard widget
