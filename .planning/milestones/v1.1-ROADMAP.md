# Milestone v1.1: Fixed ROI Calculations

**Status:** ✅ SHIPPED 2026-02-01
**Phases:** 6-7
**Total Plans:** 7

## Overview

Fix calculation accuracy for spotprisoptimering, stodtjanster, and effektavgifter with transparent breakdowns showing how each savings number is derived.

## Phases

### Phase 6: Calculation Engine

**Goal**: Salesperson can configure and calculate accurate savings for spotpris, stodtjanster, and effektavgifter

**Depends on**: Phase 5 (v1.0 complete)

**Plans**: 3 plans

Plans:
- [x] 06-01: Fix formulas, add constants, install Sonner
- [x] 06-02: Extend store, create slider control components
- [x] 06-03: Integrate controls into results view

**Details:**

Requirements covered: SPOT-01, SPOT-02, SPOT-03, GRID-01, GRID-02, GRID-03, GRID-04, PEAK-01, PEAK-02, PEAK-03

Success criteria delivered:
1. ✓ Spotpris calculation uses correct formula (spread × efficiency × cycles × capacity × days)
2. ✓ Stodtjanster shows Emaldo zone-based guaranteed income (SE1-SE3: 1,110 SEK/mo, SE4: 1,370 SEK/mo for 36 months)
3. ✓ Effektavgifter slider lets salesperson control peak shaving level respecting battery capacity limits
4. ✓ High cycles warning appears when warranty life tradeoff applies (>2 cycles/day)
5. ✓ All three savings categories show in calculation results with correct values

### Phase 7: Calculation Transparency & Manual Overrides

**Goal**: Prospects can see how each savings number is derived while sensitive business data stays hidden. Salesperson can manually override any calculation value with instant sync to shared links.

**Depends on**: Phase 6

**Plans**: 4 plans

Plans:
- [x] 07-01: Create breakdown components (ExpandableBreakdown, Spotpris, Effekt, Stodtjanster)
- [x] 07-02: Extend types and integrate breakdowns into public view
- [x] 07-03: Override infrastructure (schema, types, store, OverridableValue component)
- [x] 07-04: Override integration (save action, public apply, admin UI)

**Details:**

Requirements covered: SPOT-04, GRID-05, PEAK-04, TRANS-01, TRANS-02, TRANS-03, TRANS-04, OVRD-01, OVRD-02, OVRD-03, OVRD-04

Success criteria delivered:
1. ✓ Each savings category has expandable breakdown showing calculation inputs
2. ✓ Prospect view displays all savings breakdowns with battery price
3. ✓ Prospect view hides margins, org cuts, and internal business data
4. ✓ Breakdown shows the formula/logic used to derive each savings number
5. ✓ Salesperson can manually override any savings total or input value
6. ✓ Overrides sync instantly to already-shared calculation links
7. ✓ Overrides are invisible to prospects (they see adjusted values as calculated)

## Milestone Summary

**Key Decisions:**

| Decision | Rationale | Phase |
|----------|-----------|-------|
| Keep calcSpotprisSavings and add calcSpotprisSavingsV2 | Backwards compatibility | 06-01 |
| Custom Sonner component without next-themes | Project uses custom dark mode | 06-01 |
| Constraint functions return structured objects | Rich UI feedback | 06-01 |
| No debounce on slider changes | Zustand performant enough | 06-02 |
| totalProjectionYears default 10 | Standard ROI period | 06-03 |
| Emaldo detection via brand name | Simple heuristic | 06-03 |
| currentPeakKw placeholder 8 kW | Until customer data available | 06-03 |
| Button + motion.div over native details/summary | Full animation control | 07-01 |
| Build breakdown server-side | Security, prevents manipulation | 07-02 |
| Null-based override semantics | Clearer intent, JSON-friendly | 07-03 |
| Inline edit with hover icons | Lower friction | 07-03 |
| Apply overrides server-side before public view | OVRD-04 compliance | 07-04 |
