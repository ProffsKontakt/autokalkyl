## Issues Resolved Post-Audit

### Critical: handleFinalize Using Hardcoded Defaults

**Date:** 2026-02-01
**Severity:** Critical
**Discovered:** Production testing showed public view had different payback period than salesperson view

**Issue:** `handleFinalize` in `calculation-wizard.tsx` was using:
- `DEFAULT_CYCLES_PER_DAY` (hardcoded 1.0) instead of `store.cyclesPerDay`
- Missing `peakShavingPercent`, `postCampaignRate`, `elomrade`, `isEmaldoBattery` entirely

**Impact:** When salesperson clicked "Slutför kalkyl", the saved results used wrong default values. The salesperson saw accurate calculations (using store values), but the database stored results calculated with defaults. Public view read from database → wrong numbers shown to prospects.

**Fix:** Updated `handleFinalize` to use actual slider values from store, matching ResultsStep logic. (commit `b1c7319`)

**Root Cause:** The v1.1 slider controls were added to ResultsStep but handleFinalize wasn't updated to match.

**Prevention:** Future phases modifying calculation parameters should verify both display AND save paths use the same values.
